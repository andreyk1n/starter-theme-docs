WP_Query цикл

WP_Query — це основний клас WordPress, який використовується для отримання записів із бази даних. Він дозволяє створювати кастомні цикли постів і повністю контролювати те, які записи будуть відображатися на сторінці. На відміну від стандартного WordPress Loop, WP_Query дозволяє задавати параметри запиту: тип записів, кількість постів, категорії, сортування та інші фільтри.

Принцип роботи досить простий. Спочатку створюється масив параметрів запиту, після чого створюється об'єкт WP_Query. Далі перевіряється, чи є записи у результаті запиту, і запускається цикл, який перебирає кожен пост. Усередині циклу можна використовувати стандартні функції WordPress для виведення заголовка, посилання, уривка тексту або зображення. Після завершення циклу важливо повернути глобальні дані поста до початкового стану. 


<?php

$args = [
    'post_type' => 'post',
    'posts_per_page' => 3
];

$query = new WP_Query($args);

if ($query->have_posts()) :
    while ($query->have_posts()) : $query->the_post();
?>

<article class="post-card">
    <h2><?php the_title(); ?></h2>
    <p><?php the_excerpt(); ?></p>
    <a href="<?php the_permalink(); ?>">Read more</a>
</article>

<?php
    endwhile;
    wp_reset_postdata();
endif;

?>

Основна інформація

WP_Query використовується для створення окремих блоків контенту на сторінці. Найчастіше його застосовують для виведення останніх новин, пов’язаних статей, постів певної категорії або записів кастомного типу. Такий підхід дозволяє створювати незалежні контентні блоки у різних частинах сторінки без зміни основного запиту WordPress.

💡 Після завершення циклу завжди використовуйте функцію wp_reset_postdata(), щоб відновити глобальний об’єкт поста і уникнути помилок у наступних циклах.

Параметри

Поведінка WP_Query визначається параметрами запиту. Найчастіше використовуються параметри для визначення типу записів, кількості постів та сортування результатів. Наприклад, параметр post_type задає тип контенту, posts_per_page визначає кількість записів, які потрібно отримати, а order та orderby контролюють порядок сортування результатів.

Parameter Description Example
post_type Type of posts to retrieve post
posts_per_page Number of posts in the query 6
orderby Sorting field date
order Sorting direction DESC

Рекомендації

WP_Query найкраще використовувати для створення кастомних контентних блоків на сторінці. Наприклад, для відображення останніх записів блогу, слайдерів, пов’язаних постів або спеціальних секцій на головній сторінці сайту. У більш складних проєктах розмітку поста бажано винести у окремий template part, щоб зробити код більш модульним та зручним для підтримки.

Також рекомендується обмежувати кількість записів у запиті та уникати надто складних фільтрів, щоб не створювати зайве навантаження на базу даних. Якщо потрібно змінити основний запит сторінки, краще використовувати фільтр pre_get_posts, а не створювати новий запит у шаблоні.
